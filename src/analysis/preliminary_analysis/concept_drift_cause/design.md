# concept_drift_cause 設計書（Phase1 / 特徴量の寄与度分析：精度変動の原因をモデル側から説明する）

## 0. 位置づけ・要旨

距離×時期行列の分析（`concept_drift_detection`）の距離×時期行列で見えた**精度の上下が、モデルの何によって起きたのか**を、特徴量の使い方から説明する分析。

- **手法**：Integrated Gradients（以下 IG）。**入力の 15 特徴量**に対して、モデルの出力をどちら向きにどれだけ押したかを符号付きで配分する。
- **見るモデル**：距離×時期行列の分析の**そのセルの値を出したモデルそのもの**。距離×時期行列の分析は `N_REPEATS = 5`（奇数）なので、各評価日・各距離で AUC が中央だった seed が一意に決まる（`concept_drift_detection/design.md` §6.5, §8.1）。
- **分けて見る軸**：正解ラベルで **正例群／負例群**に分け、それぞれ 15 次元のプロファイルを出す。
- **対照**：同じ seed の**汎用ヘッド**のプロファイルも出す。汎用ヘッドは重みが更新されないので、その変化は**データが変わった分だけ**を表す。
- **出力**：計算結果（`ig_daily.csv.gz`）・表（`extract/`）・図（`figures/`）の 3 段。図は**セル 1 つを 1 枚の横向き発散棒グラフ**にしたものと、それを距離の行・位置の列ごとに格子状に並べた一覧の 2 種類（§9.4）。
- **本ディレクトリでは事前学習も probe 学習もしない**。エンコーダは `pretrained_encoders` から、probe は距離×時期行列の分析が保存したものを load する。
- **距離×時期行列の分析を先に回し終えている必要がある**（probe と日次指標の両方を使うため）。

---

## 1. 目的と問い

距離×時期行列の分析で得られた距離×時期行列は「**いつ・どれだけ古い学習データだと精度が落ちるか**」を示したが、「**なぜ落ちたか**」は答えない。精度が落ちる原因は大きく 2 つある。

| | 原因 |
|---|---|
| (a) | **データ側の変化**：入力される Change の分布そのものが変わった |
| (b) | **モデル側の変容**：同じ入力に対する重みづけが変わった |

**特徴量の寄与度分析が扱うのは (b)**。IG は正解ラベルも精度も使わずに計算できるため、「精度が低い理由を精度で説明する」という循環に陥らない。

(a) のデータ側の分析（特徴量単体の AUC など、モデルに依存しない手法）は **特徴量の寄与度分析の実装後に別途行う**（§13）。

## 2. 手法：Integrated Gradients

### 2.1 なぜ IG か（permutation importance を採らない理由）

| | permutation importance | **Integrated Gradients** |
|---|---|---|
| 正例群・負例群に分ける | **不可**（精度指標は両クラスが必要） | 可 |
| 符号（押し上げ／押し下げ） | **出ない** | 出る |
| 精度との循環 | **ある**（精度の低下量で定義される） | ない |
| 1 日あたり正例 4.5 件で安定するか | **しない** | する（1 件ごとに計算する） |
| 相関した特徴量 | **歪む**（実在しない Change ができる） | 歪まない |
| 実装の重さ | 軽い | 重い |

**①②だけで成立しない**ため IG を採る。①は決定的で、精度指標は正例と負例の両方が揃わないと計算できないため、**正例群だけ／負例群だけを取り出した permutation importance は原理的に作れない**。

なお permutation importance は、§13 のデータ側の分析では有力な道具になる。

### 2.2 対象出力は「ロジット」

モデルの最終出力は `シグモイド(ロジット)` で確率になるが、**IG はシグモイドを通す前のロジットに対して取る**。理由は 2 つ。

**① 飽和を避けるため。** 正例率は 1.9〜8.4% しかなく、大半の Change はシグモイドの平坦な領域にいる。シグモイドの傾きは `確率 ×(1−確率)` なので、確率 0.02 の Change では確率 0.5 の Change の **13 分の 1**、確率 0.002 では **125 分の 1** に縮む。確率に対して IG を取ると、モデルの感度と無関係にこの倍率がかかる。
  - とくに**負例群はほぼ全員が平坦域**にいるため、確率で取ると負例群の IG だけが一律に潰れ、**§3.2 の正例群と負例群の比較が成立しなくなる**。
  - 実測（nova 30.0.0）でも、しきい値 0.5 での recall は平均 0.0074＝ほぼ全件が負例側に張り付いている。

**② §2.5 の線形分解を保つため。** 間にシグモイドが挟まると分解が崩れる。

### 2.3 基準点は「その日の集合の平均」

IG は「基準点から実際の値まで動かしたとき、出力がどれだけ動いたか」を特徴量ごとに配分する。その**出発点（基準点）**をどこに置くかを決める必要がある。

- **基準点 ＝ その評価日の集合（Open な Change 全体）の平均ベクトル**。
  - ゼロは使えない（`追加行数 0 行` の Change は実在するので「何もない状態」にならない）。
  - この置き方だと IG は「**この Change は、その日の平均的な Change と比べて、どの特徴量のせいでスコアが上下したか**」を答える。
- **動かすのは対象 Change だけ**。同じ日の他の Change は**実際の値のまま固定する**。
  - エンコーダは自己注意を使うため、ある Change の内部表現は同じ日の他の Change にも依存する。集合全体を一緒に動かすと、IG が「自分の特徴量の寄与」と「周囲の集合が変わった影響」の混合物になり、15 特徴量に配分する意味がなくなる。
  - 固定することで「**その日の実際の文脈の中で、その Change 自身の特徴量が効いた分**」が測れる。
- **標準化は IG の値に影響しない**。特徴量は標準化してからエンコーダに入るが、標準化は特徴量ごとに定数を引いて定数で割るだけなので、勾配側と差分側で打ち消し合う。したがって値は**元の特徴量に対するもの**としてそのまま読める。基準点も、標準化の前に平均を取っても後に取っても同じ点になる。

### 2.4 積分の刻み

- **32 段階**（`IG_STEPS = 32`、constants で変更可）。基準点から実際の値までを 32 等分し、各点で勾配を測って足し合わせる。
- **15 個の特徴量は同時に動く**（1 個ずつ動かすのではない）。

### 2.5 線形プローブであることの帰結

ヘッドは `nn.Linear(128, 1)` なので、ロジットは `重み · 内部表現 + 切片` という掛けて足すだけの形をしている。したがってロジットに対する IG は次に分解できる。

```
IG = 翻訳表（エンコーダ由来） × ヘッドの重み

  翻訳表 ＝ 「ある特徴量を基準点から実際の値まで動かしたとき、
              128 次元の内部表現がどれだけ動くか」を表す 15 × 128 の行列
```

ここから 2 つ言える。

**① 距離ごとのプロファイルの違いは、probe の重みの違いだけから来る。** 翻訳表はエンコーダとその日のデータだけで決まり、距離に依存しない。同じ評価日・同じ seed なら翻訳表は完全に同一なので、**距離を変えてプロファイルが変わったなら、原因は probe の重みが変わったこと以外にない**。特徴量の寄与度分析が測りたい「モデル側の変容」そのものを測っていることの裏づけになる。

**② 「重みを直接比べればよいのでは」への答えになる。** 重みは 128 次元の内部表現の空間にあり、「埋め込みの 2 次元目」には意味がない。**翻訳表がそれを 15 個の特徴量の言葉に引き戻す**。これが IG を使う理由である。

**注意**：この性質は**同じ seed の中でのみ厳密に成立する**（翻訳表は seed ごとに違うエンコーダから来るため）。§4 の通り距離ごとに選ばれる seed は入れ替わりうるので、その点は §5 の汎用ヘッドで部分的に補う。

## 3. 分割の軸と読み方

### 3.1 正解ラベルで正例群／負例群に分ける

- その評価日の Change を**正解ラベル**（Δ=1 日以内に人間レビューが付いたか）で 2 群に分け、**群ごとに 15 次元のプロファイル**を作る。
- 群の中では、各 Change の IG を**単純平均**する。
- **モデルに依存しない分け方**なので、別のモデル同士でも同じ Change 群を比較できる。

### 3.2 読み方

**① モデル間比較（同じ群同士）**

距離を変える／時期を変えると精度がどう変わるかは距離×時期行列の分析が示している。その横に同じ群のプロファイルを並べる。

> セル X（距離 d0）は AUC 0.669、セル Y（距離 d5）は AUC 0.488。
> このとき**正例群**のプロファイルは X で `追加行数` が強く効き、Y ではほぼ効いていない。

**② 群間比較（同一モデルの正例群 vs 負例群）**

| パターン | 読み |
|---|---|
| 正例で ＋、負例で − | **識別に効いている**（正例を押し上げ負例を押し下げる） |
| 正例・負例とも同じ向き | **一律に押し上げているだけで識別に寄与していない** |
| 両方とも 0 付近 | その特徴量を**見ていない** |

### 3.3 4 象限（TP/FP/FN/TN）を使わない理由

予測で分ける（正例と予測／負例と予測）と、**部分集合がモデルごとに変わる**。すると「A のモデルの TP」と「B のモデルの TP」は**中身の Change が違う**ため、プロファイルを並べても比較にならない。

正解ラベルで分ければ部分集合はモデルに依存しないので、比較が成立する。4 象限は**誤り診断の補助ビューとしてのみ**将来の拡張に残す（§13）。

### 3.4 負例側の「正答率」を作らない理由

「正例群は正例と当てられたか／負例群は負例と当てられたか」を両方出したいところだが、**負例側は原理的に動かない**。

| project | recall@10（正例側） | specificity@10（負例側） | 負例の平均正規化順位 |
|---|---|---|---|
| nova | 0.207 **sd 0.279** | 0.9646 sd **0.0052** | 0.5049 sd **0.0043** |
| neutron | 0.387 sd 0.296 | 0.8774 sd 0.0373 | 0.5214 sd 0.0202 |
| glance | 0.596 sd 0.404 | 0.7414 sd 0.0455 | 0.5150 sd 0.0184 |

負例が全体の 92〜98% を占めるため、**負例群の平均はほぼ全 Change の平均に固定される**。これは不均衡そのものから来る制約で、定義を変えても回避できない。したがって**精度はセルに 1 組だけ添え、正例行・負例行で同じ値を入れる**（§7）。

## 4. どのモデルを見るか

**距離×時期行列の分析のそのセルの値を出したモデル**を見る。特徴量の寄与度分析は距離×時期行列の分析の精度の裏側を説明するものなので、距離×時期行列の分析が参照していないモデルを見ても対応が付かない。

```
①距離×時期行列の分析の daily_metrics.csv.gz を読む
        ↓
② (評価日, 距離) ごとに、5 seed の AUC を並べて 3 番目（中央）の seed を特定する
   →距離×時期行列の分析のその日の値を出したモデルそのもの（N_REPEATS が奇数なので一意）
        ↓
③ その seed の probe だけで IG を計算する
```

- **選択の基準は AUC**。recall@k は正例が少なく（nova で 1 日あたり中央値 4.5 件）**取りうる値が数段階しかない**ため、5 個のモデルを順位づけられない（10 seed で実測すると recall@10 は中央 2 個が同値になる割合が 86.0%、AUC は 4.4%）。AUC は全ペアを使う連続値なので順位が一意に決まる。
  - なお**表に載せて考察する指標は recall@5/10/20 で構わない**（§7）。「順位づけの基準」と「報告する指標」は役割が別。
- **同値の場合は seed 番号の小さい方**を採用する（距離×時期行列の分析と同じ規則）。
- **選択は評価日ごと・距離ごとに行う**。同じ日でも距離が違えば AUC の順位が変わるので、選ばれる seed は入れ替わりうる。
  - この結果、距離間の比較に「エンコーダの違い」が混ざる可能性がある。**これは承知のうえで受け入れる**：そのモデルがなぜその特徴量を使ったのかを知りたいのであって、エンコーダもそのモデルの一部である。§5 の汎用ヘッドを引くことで部分的には正規化される。
- 距離×時期行列の分析は「日ごとに seed 中央値 → 日で平均」で集約するので（`concept_drift_detection/design.md` §8.1）、**選ばれたモデルの日次値を日で平均すると距離×時期行列の分析のセル値に一致する**。精度とプロファイルが同じモデル・同じ日から出てくる。

**計算量への影響**：5 個のうち 1 個しか計算しないため、全 seed を計算する場合の **10 分の 1**（当初案は 10 seed 全部を計算する想定だった）。

## 5. 汎用ヘッド

### 5.1 何のために使うか

probe と汎用ヘッドは、どちらも**同じ凍結エンコーダの上に載る最後の 1 層**で、違いは学習データだけ。

| | 汎用ヘッド | probe |
|---|---|---|
| 学習データ | 事前学習データ全体（cutoff より前） | 評価日から距離 `d` 段遡った窓長ぶんの期間 |
| その後の更新 | **一切なし。全セル・全時期で同じ** | セルごとに貼り直す |

したがって §2.5 の分解を当てはめると、

| | プロファイルが変わる原因 |
|---|---|
| **probe** | 重みの変化（**モデルの変容**）＋ 翻訳表の変化（**データの変化**） |
| **汎用ヘッド** | **翻訳表の変化のみ**（重みが固定のため） |
| **差** | **モデルの変容だけ** |

汎用ヘッドは「**データが変わっただけならプロファイルはこれだけ動く**」という物差しになる。

### 5.2 効き方は方向によって違う

- **時期方向（位置 `p` を変える＝違う日を比べる）**：データが変わるので翻訳表が変わる。→ **汎用ヘッドが効く**。
- **距離方向（距離 `d` を変える＝同じ日で学習期間だけ変える）**：評価するデータは同じ日なので、**同じ seed なら翻訳表も同じ**。汎用ヘッドのプロファイルは距離が変わっても動かず、引いても距離間の差は変わらない。
  - ただし §4 の通り距離ごとに seed が入れ替わるため、実際には汎用ヘッドも距離ごとに変わる。このとき各 seed の中で汎用ヘッドを引いておくと、**そのエンコーダ固有の癖が正規化される**。距離方向でも無駄にはならない。

### 5.3 seed は必ず probe に合わせる

**汎用ヘッドは、その距離で選ばれた probe と同じ seed のものを使う。** 汎用ヘッド自身の精度で選び直してはいけない。

理由：同じ seed なら probe と汎用ヘッドが**同じエンコーダ＝同じ翻訳表**を共有するため、引き算で翻訳表が打ち消え、差が**重みの違いだけ**を表す。違う seed だと翻訳表が残り、差に「エンコーダ A と B の違い」が紛れ込む。

架空の数字で示すと、汎用ヘッドの重みが両方まったく同じでも、翻訳表が違えば IG は違う値になる。

| | `追加行数` の IG |
|---|---|
| probe（エンコーダ④の上） | 1.00 |
| 汎用ヘッド（エンコーダ④の上） | 0.80 → **同じ seed で引くと 0.20（正しい）** |
| 汎用ヘッド（エンコーダ①の上） | 0.70 → 違う seed で引くと 0.30（**5 割過大**） |

### 5.4 距離×時期行列の分析の差分行列との違い

**距離×時期行列の分析の差分行列は seed を揃えない**（probe 行列と汎用ヘッド行列の単純な引き算）。扱っているのが精度というスカラーで、打ち消すべき翻訳表が存在しないため。

**特徴量の寄与度分析の差分は seed を揃えることが必須**。15 次元の寄与度を引くので、翻訳表を打ち消す必要がある。同じ名前でも意味が違う点に注意。

### 5.5 計算量

汎用ヘッドは**距離に依存しない**ので、1 評価日につき**その日に選ばれた seed の種類数ぶん**（最大 5 本）計算すれば足りる。probe は距離 26 本ぶん必要なので、**追加は最大でも 19%**（5/26）。

## 6. 対象範囲

### 6.1 セルの指定

**全セルを一律に回すのではなく、`constants.IG_TARGETS` で指定したセルだけを計算する。**

```python
# project -> version -> {"distances": [...] or "all", "positions": [...] or "all"}
IG_TARGETS = {
    "nova":     {"30.0.0": {"distances": "all", "positions": "all"}},
    "neutron":  {"25.0.0": {"distances": "all", "positions": "all"}},
    ...
}
```

- **距離と位置をそれぞれリストで指定し、その直積**を対象とする。`"all"` でその軸すべて。
  - 考察は**縦（距離を変える＝モデルの経年変化）と横（位置を変える＝時期の違い）**で行うため、行・列をまとめて指定できる形にする。
- CLI（`--project` / `--version` / `--distances` / `--positions`）で**上書きできる**が、**既定は constants**。
- 版をまたぐときは、`IG_TARGETS` に最新版だけを書いて回し、結果を見てから古い版を追記する運用を想定する（出力は追記式。§9.2）。

### 6.2 実行の順序

**プロジェクトごとのループを維持する。** 1 プロジェクトの Change 読み込みは nova で 3.2GB・約 5.5 分、全 6 プロジェクトで 1 周あたり約 13 分かかるため、読み直しを増やさない。

「各プロジェクトの最新版だけ先に確認する」という使い方は、**`IG_TARGETS` に最新版だけを書けば読み込み 1 周で達成できる**（世代順のループは実装しない）。

なお日ごとの集合のキャッシュは**入れない**。全セルを一括で回す使い方なら読み込みは全体の 1.5% 程度で、キャッシュの効果が小さいため。

### 6.3 欠測日の扱い

**距離×時期行列の分析と同じ条件で落とす**（正例 0 件／負例 0 件／集合 30 件未満／その距離の probe が学習できない）。正例が 0 件の日は正例群のプロファイルが作れず、精度も定義できないため、**日ごと丸ごと落とす**。負例群だけ残すことはしない（正例群と負例群で日の集合がずれると比較が濁るため）。

欠測の補完や、欠測の多いセルの除外は**行わない**。

### 6.4 IG を計算する Change

**その評価日の Open な Change を全件計算する。** 正例は 1 日あたり中央値 2.6〜6.0 件しかないので当然として、負例（1 日あたり 34〜256 件）も間引かない。

間引くとプロファイルが標本の取り方に左右され、セル間の差を読むときにその影響を切り分けられなくなる。全件でも最新版・全セルが一晩で終わる規模なので（§10）、精度を落としてまで短縮する理由がない。

## 7. 精度の付与

各セルに **AUC / recall@5 / recall@10 / recall@20** の 4 つを添える。

- **k = 5, 10, 20** は従来研究（Azeem 2020, AR-Prioritizer）の top@5/10/20 に合わせる。同論文の Average Recall は `top@N に入った正例数 ÷ 正例総数` で、**本研究の recall@k と同一の定義**。
  - ただし Azeem の評価は「正例率 25% の 40 件から上位 10 件」、本研究は「正例率 1.9〜8.4% の 34〜256 件から上位 10 件」なので、**タスク設定が異なり数値の直接比較はできない**。考察でこの点を明記する。
  - **主として議論する k は結果を見てから決める**（10 か 20）。
- **精度 4 列は正例行・負例行で同じ値**を入れる。これは「群」ではなく「そのセルのモデル」の良し悪しを表すため（§3.4）。
- **距離×時期行列の分析の `daily_metrics.csv.gz` から `(評価日, 距離, seed)` で結合する**。追加計算はしない。
- **集約は距離×時期行列の分析と同じ順序**（日ごとに seed 中央値 → 位置の日数で平均）。§4 の通り特徴量の寄与度分析が選ぶモデルは各日の中央モデルそのものなので、**距離×時期行列の分析のセル値と一致する**。
- **IG を計算した日に限定して集計する**。正常に完走すれば距離×時期行列の分析と同じ日になるが、途中で中断した場合に精度とプロファイルが別の日を見ている状態を防ぐ。
- **汎用ヘッドの行に添える精度は、その行のモデル（probe で選ばれた seed）の汎用ヘッドの AUC**。距離×時期行列の分析の汎用ヘッド行列の値（汎用ヘッド自身の中央モデル）とは異なる数字になるが、「その行のプロファイルを出したモデルの精度を載せる」という原則を優先する。

## 8. 集約

```
① (評価日, 距離) ごとに、§4 で選ばれた seed の probe / 汎用ヘッドで
   正例群・負例群それぞれの 15 次元プロファイルを作る
   probe − 汎用ヘッドの差も、この段階で同じ seed 同士で引く（§5.3）
        ↓
② セル内の日で平均      → セルの値
   セル内の日で標準偏差  → std（日間のばらつき）
   有効日数              → 列に出す
```

- **std は「日間のばらつき」**。平均だけを見て解釈する事故を防ぐ（平均としては効いているが日によって全く違う特徴量を見分けるため）。
- **seed 間のばらつきは出せない**。1 日につき 1 個のモデルしか計算しないため。必要になったら 1〜2 セルだけ 5 seed 全部の IG を計算して確認する（5 倍のコスト＝nova の 1 セルで約 14 分）。
- **有効日数を必ず列に出す**。セルあたりの有効日数はプロジェクトによって大きく違う（中央値で nova 5 日／neutron 6 日／cinder 12 日／glance 4 日／keystone 1 日／swift 42 日）ため、std が何日から計算されたかを読み手が判断できるようにする。

## 9. 出力

```
data/analysis/preliminary_analysis/concept_drift_cause/
  <project>/set_transformer/<version>/
      ig_daily.csv.gz        … 計算の出力（評価日 × 距離 × ヘッド × 群）
      ig_daily_meta.json     … 実行条件の履歴
      extract/<名前>/        … 抽出の出力（表）
      figures/               … 作図の出力（§9.4）
```

### 9.1 計算の出力：`ig_daily.csv.gz`

集約する前の**最も細かい単位**で保存する（距離×時期行列の分析の `daily_metrics.csv.gz` と同じ考え方）。

| 列 | 内容 |
|---|---|
| `run_id` | その実行の識別子（実行開始日時。例 `20260920T1432`） |
| `day` / `position` / `distance` / `seed` | 距離×時期行列の分析と同じキー（そのまま結合できる） |
| `head` | `probe` または `general` |
| `group` | `pos`（正例群）または `neg`（負例群） |
| `n_changes` | その群で IG を計算した Change 件数 |
| 15 列（`bug_fix_confidence` 〜 `refactoring_confidence`） | その群の IG の平均（**生の値**） |

- **横長**（1 行に 15 特徴量を並べる）。縦長にすると行が 15 倍になり、表を作るたびに pivot が要る。
- **汎用ヘッドの行は `(評価日, seed)` で持つ**（`distance` は `"general"`）。汎用ヘッドは距離に依存しないため、1 日につき**その日に選ばれた seed の種類数ぶん**（最大 5 本）でよい。距離ごとに 26 本作ると同じ内容が重複する。
  - 抽出時は probe 行の `seed` を見て、**同じ `(評価日, seed)` の汎用ヘッド行を引く**ことで自動的にペアになる。
- **寄与率は保存しない**。IG の完全性（15 個の合計 ＝ ロジットの差）より、寄与率は生の値から `その特徴量の IG ÷ 15 個の合計` で完全に復元できる。保存すると列が倍になり中身が重複する。**抽出時に生の値と寄与率の両方を出す**。
- **差分（probe − 汎用ヘッド）も保存しない**。同じ `(評価日, seed)` の行同士で引けるため、抽出時に作る。

### 9.2 追記とメタ情報

- **追記式**。同じ `(version, day, distance, seed, head, group)` の行があれば、新しい実行の行で**置き換える**。
- `ig_daily_meta.json` に **`run_id` ごとの実行条件**を履歴として蓄積する（積分の段階数・基準点・対象セル・実行日時・git commit）。
  - 日時だけを列に持たないのは、知りたいのが「いつ計算したか」より「**どの条件で計算したか**」だから。段階数や基準点を変えて再実行すると条件の違う行が同じファイルに混ざるため、`run_id` を鍵にして辿れるようにする。
- **条件が違う実行を検出したら警告を出す**（黙って混ざるのを防ぐ）。

### 9.3 抽出の出力

**表 1（セル × 特徴量）**を、`probe_pos` / `probe_neg` / `general_pos` / `general_neg` の **4 ファイル**に分けて出力する。1 つの表に混ぜると行が 4 倍になり読みにくいため。

| 距離 | 位置 | AUC | r@5 | r@10 | r@20 | 日数 | `lines_added` | … |
|---|---|---|---|---|---|---|---|---|
| d0 | p13 | 0.669 | … | 0.222 | … | 4 | +0.12 ± 0.04 | … |
| d5 | p13 | 0.488 | … | 0.028 | … | 4 | +0.02 ± 0.05 | … |

- **`utf-8-sig`（BOM 付き）で保存**する（Excel で開いたときに文字化けしないように）。
- **計算と抽出を分離する**。重い計算は一度だけ回して保存し、**どのセル・どの特徴量を考察対象にするかは後から何度でも切り出せる**ようにする。考察対象を事前に決めておく必要がない。

### 9.4 作図の出力

#### 9.4.1 何を描くか：差分（probe − 汎用ヘッド）

**既定で描くのは差分**（同じ `(評価日, seed)` の probe と汎用ヘッドを日ごとに引いてから、セル内の評価日で平均）。probe 単体・汎用ヘッド単体は constants で任意に生成する。

差分を主にする理由は 3 つある。

1. **距離・時期による変化が見やすくなる**。nova の `elapsed_time`（正例）は probe そのままだと距離 0 で 2.436、距離 16–25 で 2.166 と 1 割ほどしか動かないが、差分にすると 0.440 → 0.208 と**半分以下**になる。probe の値の大部分は汎用ヘッドと共通の土台であり、距離で動いているのはその上に乗った部分だから。
2. **ばらつきが減る**。同じ実測で、日ごとの変動幅が 1.92 → 1.39、1.42 → 0.97 に縮む。§2.5 のとおり `IG ＝ 翻訳表（encoder とその日のデータで決まる）× プローブ重み` なので、同じ `(評価日, seed)` なら翻訳表が共通で、引くと相殺される。
3. **距離による変化量そのものは保たれる**。汎用ヘッドは距離に依存しない（§5.3）ので、引いても距離間の差は残る。実測でも距離 0 と距離 16–25 の差は `elapsed_time` が +0.269 → +0.232、`past_report_count` が +0.117 → +0.119 とほぼ変わらない。

**汎用ヘッド単体は距離・位置で変化しない**ので、格子に並べても同じ図が 26 枚並ぶだけになる。単体で見たい場合は seed ごとに 1 枚あれば足りる。

#### 9.4.2 2 種類の図（ペアで作る）

| 種類 | 1 枚の単位 | 枚数（差分のみ・6 project 合計） |
|---|---|---|
| 個別セル図 | `(距離, 位置)` の組 1 つ | 2,216 セル × 正例/負例 ＝ **4,432 枚** |
| 格子一覧 | 距離の行 1 つ／位置の列 1 つ | (100 ＋ 99) × 正例/負例 ＝ **398 枚** |

- **格子一覧は個別セル図を並べたもので、集約はしない**。1 パネル ＝ 1 セルであり、中身は個別セル図と同一。「距離 0 の 182 日を平均して 1 本の棒にする」ような図は**作らない**（セル間の比較が目的であり、行をまとめると比較する単位そのものが消えるため）。
- 個別セル図と格子一覧は**必ずペアで生成する**。格子で気になったセルを個別図で開く、という使い方を前提にする。

#### 9.4.3 棒の描き方

- **横向きの発散棒グラフ**。中央を 0 とし、負は左・正は右に伸ばす。
- 棒の長さは**セル内の評価日をまたいだ平均**（§8 の集約と同じ）。
- **15 次元すべてを `FEATURE_NAMES` の定義順**に並べる。並び順を図ごとに変えると比較できない。
  - `days_to_major_release` / `open_ticket_count` / `reviewed_lines_in_period` は**構造上すべての図でゼロになる**（`t` と project だけで決まり、同じ日の集合内で全 Change が同じ値をとるため、基準点との差が 0）。図には載せるが注記はしない。

#### 9.4.4 ばらつきの表示

| | エラーバー | 数値 |
|---|---|---|
| 個別セル図 | 標準偏差を棒の**先端を中心に**引く | `+1.81 (±0.54)` を棒の右に添える |
| 格子一覧 | 描かない | 描かない |

- **個別セル図は両方描く**。エラーバーは「ゼロをまたぐか」＝**符号が定まっているか**が一目でわかり、数値は正確な値が読める。それぞれ独立に constants でオンオフでき、**既定はどちらもオン**。
- **格子一覧はどちらも描かない**。1 枚に最大 26 パネル × 15 本 ＝ 390 本入るため、線を足すと 780 本になって潰れ、文字は小さすぎて読めない。格子は傾向を見比べる用途と割り切り、ばらつきは個別セル図で確認する。
- ばらつきの表示が要る理由は、**平均だけでは「効いていない」と「日によって逆向きに効いている」を区別できない**から。nova の距離 0 × 位置 1（正例）の `revision_count` は 7 日の値が −0.794 〜 +0.660 で符号が反転しており、平均は −0.056 になる。棒だけだと「効いていない」と読めるが、実態は違う。
- 実測では `標準偏差 ÷ |平均|` が `elapsed_time` で 0.5、他は 1.7〜2.3 と**1 を超える**（＝符号が定まらない）。

#### 9.4.5 軸

- **プロジェクト × 系列（差分/probe/汎用 × 正例/負例）ごとに共通の目盛り**にする。個別セル図と格子一覧も同じ目盛りを使う。
  - 図ごとに自動設定すると、目盛りが違うだけで「棒が伸びた」ように見えて誤読する。
  - プロジェクトをまたいで揃えると glance（最大 10.69）に合わせることになり keystone（2.05）が読めない。正例と負例を揃えると、桁が違う（nova 正例 7.60 / 負例 1.80）ため負例が潰れる。
- **端は「平均 ＋ 標準偏差」の 95 パーセンタイル**（constants で調整可）。
  - 平均だけで決めるとエラーバーが 2〜3 倍の位置まで伸びて枠外に出る（実測：nova 正例で 0.45 → 1.13）。
  - 最大値に合わせると外れ値 1 つで全体が潰れる（nova 正例は最大 7.60 だが 95% は 1.47 以下）。
  - 箱ひげ図の外れ値判定（Q3 ＋ 1.5×IQR）は**使わない**。値の大半がゼロ近辺に集中する分布のため 0.31 と極端に小さくなり、大半の棒がはみ出す。1.5×IQR は正規分布に近い形を前提にした経験則で、この分布には合わない。

#### 9.4.6 格子の並べ方

- **折り返して格子状**に並べる（26 枚なら 5 行 × 6 列で 4 枠あく、13 枚なら 3 行 × 5 列、6 枚なら 2 行 × 3 列）。一列に並べると幅 6,700px の帯になり扱いにくい。
- 並び順は左上から右へ、距離の行なら位置 1, 2, 3 …、位置の列なら距離 0, 1, 2 …。
- **特徴量名は各行の左端パネルにのみ**表示する。全パネルに書くと埋まる。
- **空のセルは枠を確保したうえで「データなし」と明記**する（glance に 8 セルある）。詰めて並べると以降のパネルが 1 つずつずれ、位置番号と実際の中身が食い違う。

#### 9.4.7 タイトル

1 枚だけ見ても何の図かわかるようにする（4,830 枚あるため）。

```
nova 30.0.0  距離0 × 位置1  差分（probe − 汎用）/ 正例
AUC=0.850  評価日数=7  1日あたり正例Change数=4.7
```

- **AUC は probe の実測値**（差分ではない）。精度が落ちているセルを図だけで追えるようにするため。
- Change 数のラベルは群に合わせる（正例の図なら「1日あたり正例Change数」、負例の図なら「1日あたり負例Change数」）。

**格子一覧のパネル見出しは 2 行**にし、AUC に加えて**規模（評価日数・1日あたりChange数）も出す**。

```
位置1  AUC=0.893
2日 / 正例2.0件
```

- 規模を出すのは、**セルによって 5〜14 倍の開きがある**ため。実測（正例・probe）では次のとおりで、規模を知らずに並べると、数日ぶんの偶然で決まった棒と十分な日数の棒を同列に比べてしまう。

| project | 評価日数 | 1日あたり正例Change数 |
|---|---|---|
| nova | 3〜7 | 2.2〜10.9 |
| neutron | 5〜7 | 2.3〜12.8 |
| **glance** | **1〜7** | **1.0〜14.0** |
| keystone | 2〜12 | 2.0〜3.1 |
| cinder | 10〜14 | 2.3〜9.1 |
| swift | 17〜22 | 2.1〜3.2 |

- 2 行にすると縦を食うため、パネルの高さを 2.9 → 3.1 インチに広げる。

#### 9.4.8 出力先

```
<project>/set_transformer/<version>/figures/
├─ by_cell/          … 個別セル図
│   ├─ diff_pos/d00_p01.png, d00_p02.png, … d25_p26.png
│   └─ diff_neg/

    ├─ diff_pos/p01.png … p26.png

```

- probe 単体・汎用単体を有効にすると `probe_pos/` `general_pos/` などが同じ構成で増える。

#### 9.4.9 実行と入力

- **入力は `ig_daily.csv.gz` と距離×時期行列の `daily_metrics.csv.gz` の 2 つだけ**。`--mode extract` の出力には依存しない。
  - タイトルの AUC・評価日数・Change 数は `daily_metrics.csv.gz` から直接引く。extract に依存させると、`compute` をやり直したあと `extract` を忘れたときに**古い AUC がタイトルに入る**。

#### 9.4.10 制約

## 10. 計算量（実測）

MPS（Apple M2）での実測値。エンコーダは実際の構成（`d_model=128`・2 層・4 ヘッド）。

| | 時間 |
|---|---|
| エンコーダを 1 回通す（371 件） | 1.470 ms |
| probe で 371 件を予測する | 0.054 ms |
| **IG を対象 1 件について計算する（32 段階）** | **72.973 ms** |

**なぜ IG だけ重いか**：距離×時期行列の分析は埋め込みを 1 日 1 回計算してキャッシュし、26 距離すべてで使い回している（`@torch.no_grad()`）。IG は勾配が必要でキャッシュが使えず、しかも **32 段階 × Change 1 件ごとに別経路**でエンコーダを通し直す（IG は「その 1 件だけを基準点から動かす」計算なので、Change ごとにまとめられない）。1 日・1 seed あたりのエンコーダ通過回数は **1 回 → 11,872 回**になる。

対象 1 件あたりの時間は**集合サイズのおよそ 1.7 乗**で増える（自己注意が 2 乗で効くため、1 件の IG が欲しくてもその日の集合全体を毎回通す必要がある）。

| 集合サイズ | 30 | 73 | 129 | 207 | 261 | 387 | 480 |
|---|---|---|---|---|---|---|---|
| 1 件あたり | 2.7 ms | 8.0 ms | 17.0 ms | 31.8 ms | 45.9 ms | 80.3 ms | 106.9 ms |

**セル 1 つあたり（全 Change・1 seed・1 版）**

| project | 平均集合 | 1 セル |
|---|---|---|
| nova | 371 | 2.8 分 |
| cinder | 207 | 1.5 分 |
| swift | 128 | 1.5 分 |
| neutron | 97 | 0.1 分 |
| glance / keystone | 40 / 39 | 0.01 分 |

**まとまった単位**

| | 所要時間 |
|---|---|
| 全プロジェクトの**最新版**・全セル | **14.6 h** |
| 全プロジェクト・全 5 版・全セル | 188 h |

最新版が安いのは、古い版ほど 1 日あたりの Open Change が多いため（nova は最新版で平均 261 件、5 版通しでは平均 371 件）。

**まずは最新版を全セルで回す**のが現実的（一晩で終わる）。読み込み 13 分は全体の 1.5% で無視できる。

## 11. パラメータ（constants に集約）

- 対象：**`IG_TARGETS`**（project → version → `{"distances", "positions"}`。§6.1）。
- IG：**`IG_STEPS = 32`**（積分の段階数）、基準点の定義（その日の集合の平均・対象 Change のみ移動）。
- モデル選択：選択基準の指標（既定 **AUC**）、同値時の規則（seed 番号の小さい方）。
- 指標：`K_LIST = [5, 10, 20]`（距離×時期行列の分析と共通）。
- 出力：保存先ルート、抽出の出力先。
- 作図（§9.4）：
  - **`PLOT_SERIES`**：描く系列。既定は差分の正例・負例のみ。probe 単体・汎用単体はここに足すと個別＋格子のペアで生成される。
  - **`PLOT_SHOW_ERROR_BARS`**（既定 True）／**`PLOT_SHOW_VALUES`**（既定 True）：個別セル図のエラーバーと数値。**独立にオンオフする**（格子一覧には効かない。§9.4.4）。
  - **`PLOT_AXIS_PERCENTILE = 95`**：軸の端を決めるパーセンタイル。`平均 ＋ 標準偏差` の分布に対してとる（§9.4.5）。
  - **`PLOT_GRID_SHAPE`**：格子の折り返し方（パネル数 → (行数, 列数)。26 → (5, 6) など）。
  - **`PLOT_DPI`**：解像度。

- **勾配の経路は `pretrained_encoders` 側に「追加」する**（既存の関数は変更しない）。現状 `embed_sets` と `predict` に `@torch.no_grad()` が付いており、埋め込みも numpy でキャッシュされるため、そのままでは勾配の連鎖が切れて IG が計算できない。
  - **既存関数を書き換えない**ことで、`lookback_window` と `concept_drift_detection` には影響を与えない。
- **本ディレクトリでは事前学習も probe 学習もしない**。エンコーダは `pretrained_encoders` から、probe は距離×時期行列の分析が保存したもの（`concept_drift_detection/design.md` §6.7）から load する。

## 13. スコープ外（今回）＋ 今後

1. **データ側の分析**：特徴量単体の AUC など、モデルに依存しない手法で「入力の分布そのものがどう変わったか」を見る。§1 の (a) に対応。**特徴量の寄与度分析の実装後に着手する**。
2. **4 象限（TP/FP/FN/TN）による誤り診断**：部分集合がモデル依存なのでモデル間比較には使えないが、1 つのモデルの誤りの傾向を見る用途では有効。必要になったら追加する（§3.3）。
3. **seed 間のばらつきの確認**：1〜2 セルだけ 5 seed 全部の IG を計算し、プロファイルが seed によってどれだけ違うかを分散分解で確認する（§8）。
4. **寄与率以外の正規化**：モデルごとに出力の広がりが違うため、生の値の大小が「感度の違い」か「全体が縮んだだけ」か紛らわしい場合がある。寄与率（合計で割る）で足りなければ別の正規化を検討する。
