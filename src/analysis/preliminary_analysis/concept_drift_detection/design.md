# レビュー優先順位ドリフトの存在確認 設計書（concept_drift_detection）

## 0. このドキュメントについて

本書は事前分析①「**レビュー優先順位の判断基準が変化する区間は存在するのか**」の **再設計版** である。

旧 `concept_drift_existence`（連続 `time_to_next_review` ／ 層1・2・3の排他振り分け ／ 順位・回帰誤差・分類の3系統指標）から、以下の方針へ根本的に変更する。

- **目的変数を「計測点から Δ 以内にレビューされたか」の2値**にする（連続時間・survival をやめる）。
- **層1/2/3・排他振り分けを廃止**（同一 Change の学習/評価またぎを許容＝実運用忠実）。
- **評価は適合率・再現率・F1** に絞る。
- 実運用（毎日バックログを並べ直す）に忠実な**日次スナップショット**は維持する。

**スコープ**
- 本書は **①（F1 の d×p ドリフト行列で変化区間の存在を確認）** を対象とする。
- **②（新旧モデルの SHAP 比較による原因分析）** は、本書のモデル・データ設計をそのまま流用して後日設計する。
- **merge/reject（`decision_result`）は本書スコープ外**（後日）。

> 旧 `concept_drift_existence` は旧アプローチで既に実装・実行済みのため、本書は別ディレクトリの独立設計とする。

---

## 1. 背景と目的

- 背景：PR 投稿数の増加で「どの PR を優先的にレビューすべきか」の優先順位づけが重要になった。
- 先行研究は期間別モデルを作ったが、**期間の切り替えタイミング**は扱っていない。
- 本研究の目的：**レビュー優先順位の判断基準が変化する区間（切り替えの境目）の特定**。
- 本分析①が答える問い：そもそも **「判断基準が変化する区間」は存在するのか**。

### 1.1 概念ドリフト vs データドリフト
見たいのは **概念ドリフト（判断基準 `P(y|x)` の変化）** であって、データドリフト（入力分布 `P(x)` の変化）ではない。距離 `d` を固定して位置 `p` を横断比較する（§5）ことで、距離効果を打ち消し位置依存だけを残す。

## 2. 用語と定義

### 2.1 Change（=PR）
OpenStack / Gerrit のため PR を Change と呼ぶ。読み込みは共通ローダ（§3）。

### 2.2 計測点 `T`（毎日 0 時グリッド）とレコード
- **計測点 `T` = 毎日 0:00:00 の定点グリッド**（`MEASUREMENT_STEP_DAYS=1`、可変）。
- **1 レコード = (Change, T) の組**。長く Open な Change ほど多くの日次スナップショットに登場する（＝複数レコード）。
- 特徴量・ラベルは **その `T` 基準**で計算する。
- **実運用忠実**：実運用は毎日開いている全 PR を並べ直すため、この日次スナップショット（1 Change が複数レコード）を採用する。

### 2.3 目的変数：Δ 以内レビュー（2値）
- **正例(1)** ＝ `T` から **`Δ` 以内**に人間レビューが付く。**負例(0)** ＝ Δ 以内に付かない（Δ 超・未レビューを含む）。
- 等価に **`label = 1 if time_to_next_review(T) ≤ Δ else 0`**（旧 `time_to_next_review` の計算を流用し、しきい値で2値化）。
- **`Δ = REVIEW_HORIZON_DAYS`（既定 7 日 = 1 週間）。1 日等に変更可**（§6）。
- **人間レビュー** = ボット・投稿者本人を除いたコメント（判定は §3.3、旧実装と同一）。
- **打ち切りドロップは廃止**：未レビュー／Δ 超は**すべて負例(0)**。旧 `CENSORING_MODE="drop"` は使わない（Δ 有界なので必ず 0/1 が定まる）。

#### 2.3.1 先読み（lookahead）とマージン
- ラベル確定には `T` から **Δ 日先**を見る必要がある（＝先読み）。
- **学習側（`TRAIN_TAIL_MARGIN=True`）**：学習ビン末尾の Δ ぶんの計測点を**除外**する。学習ラベルが学習期間を超えて未来（評価期間側）を覗くリークを防ぐため。
- **評価側（`EVAL_TAIL_MARGIN=False`）**：**自主的な末尾除外はしない**（先読みでラベル付け）。評価ラベルは答え合わせでモデルに入らないためリークしない。
  - ただし **収集データの絶対末尾 Δ**（物理的に先のデータが無い計測点）は自動的にラベル不能＝除外される（設定と無関係の物理制約）。
- **除外量は Δ とビン境界の丸めに依存**：`BIN_DAY_ALIGNED=True`（§2.5）でビン境界が 0 時に揃い、`Δ = MEASUREMENT_STEP_DAYS` 日のとき、**学習側の末尾除外は厳密に 0**（末尾計測点の窓 `[T, T+Δ]` が境界とちょうど一致し、cutoff で落ちない）。この場合に残る除外は評価側の「収集データ絶対末尾 Δ」だけ。

#### 2.3.2 正例内の順位（保留）
「Δ 以内で早い/遅い」の順位や回帰は**本書では扱わない**。「Δ 以内か否か（質的な段差）」と「Δ 以内の細かい順番（連続的な差）」は別の土俵であり、混ぜて一本の relevance にしない。将来やる場合は、別指標（1週間以内限定の順位相関 / NDCG）または survival で**別々に**評価する（§8）。

### 2.4 アクティブ集合
各 `T` の対象＝ `T - LOOKBACK_DAYS ≤ created ≤ T < decision_time`（`LOOKBACK_DAYS=365`）を満たす Open な Change。

### 2.5 ビン、距離 `d`、位置 `p`
- ビン幅 = 当該リリースを `BIN_COUNT`(=6) 等分（`BINNING="equal_time"`）。同幅を前リリースへ延長。
- **`BIN_DAY_ALIGNED=True`（既定）**：基準開始を 0 時に丸め、ビン幅を**整数日に切り上げ**て、全ビン境界を毎日 0 時の計測点グリッドと一致させる。丸めの端数で末尾が最終ビンを超えた分は最終ビンへ寄せる（データ喪失防止）。境界が計測点と揃うことで、`Δ = MEASUREMENT_STEP_DAYS` 日のとき学習側の末尾除外が厳密に 0 になる（§2.3.1）。`False` で従来の秒単位等分。
- 学習候補プール = `[cycle_start − (cycle_end − cycle_start), cycle_end]`。
- セル `(i, j)`（`i<j`）：学習ビン `i`、評価ビン `j`、**距離 `d = j − i`（滞留期間）**、**位置 `p = j`**。
- 「判断基準が変わったか」は **位置 `p` の違い**で見る。精度は距離 `d` で落ちるので、**`d` 固定で `p` 横断**して距離効果を打ち消す（§5）。

### 2.6 混ぜ許容（層1/2/3 は廃止）
- **同一 Change が学習と評価に跨る（またぎ）ことを許容**する（実運用忠実を優先、楽観バイアスは受容）。
- したがって **旧 §2.6 の層1/2/3・排他振り分けは全廃**。学習＝学習ビンのレコード、評価＝評価ビンのレコード、それだけ。

### 2.7 学習/評価データの作り方
- **学習：`N_TRAIN`(=500) Change を固定数サンプリング**（全セル共通）。目的＝セル間比較可能性（学習量を揃え、精度差を判断基準の変化に帰属）。
  - 供給不足セル（`< MIN_TRAIN`）は欠測（NaN）。
  - **change-balanced 重み**：各レコードに `重み = 1/(その Change の学習内レコード数)` を付け、Change ごとの合計発言力を 1 に揃える（長寿 Change が行数で押し切る偏りを除去）。`CHANGE_BALANCED_WEIGHT`（既定 True、可変）。
    - 重みなしだと実効行数 = 500 ×(Changeあたり記録数) がセルで変動し、比較可能性が崩れる。重み付けで実効 500 Change を一定に保つ。
- **評価：全 Change（`N_EVAL="all"`）**。適合率/再現率/F1 は比率でサイズ非依存（多いほど安定・代表的・無バイアス）。
  - 極少セルは信頼性低として `MIN_EVAL` 床で扱う。
  - **重みなし（既定）**：`EVAL_CHANGE_BALANCED_WEIGHT`（既定 False、可変）。学習と非対称でよい（学習は公平化、評価は実利用の判定品質を測る）。ON にすれば長寿支配とセル間交絡を抑えられる。
- **反復**：各セルで `N_REPEATS`(=10) 回、学習 Change のサンプリングを変えて繰り返し、**`REPEAT_AGG="median"`** でセル値に集約（F1 の安定化）。
  - 注：適合率/再現率/F1 は評価レコードを**プール**して算出するため、旧 `T_AGG`（計測点 T 方向の集約）は用いない。

### 2.8 評価指標
- **適合率（precision）・再現率（recall）・F1**（正例＝Δ 以内）。3 つとも報告する。
- 2値化しきい値 **`CLASSIFY_THRESHOLD=0.5`（可変）**（sklearn/モデル既定と同じだが、後で振れるよう設定に置く）。
- 集約は評価ビン内の全レコードを**プール**。不均衡（Δ=1週で正例 ~30%）ゆえ **accuracy は主指標にしない**。
- **補助（任意）**：`AUC` / `PR-AUC` / `MCC` を後で追加可能（`ENABLED_METRICS`）。

### 3.4 特徴量
既存 `src/features/*` を `T` 時点情報で計算した **15 次元**（`review_metrics.calculate_uncompleted_requests` は除外）。developer/project 系は事前集計＋二分探索で高速化（`fast_index`、同値テストで保証）。**変更なしで流用**。

## 4. モデル

- **LightGBM ＋ RandomForest**（いずれも2値分類器）。リスト順＝実行順。
- 出力＝ P(Δ以内)。`CLASSIFY_THRESHOLD` で 2 値化して precision/recall/F1 を算出。
- 学習は `sample_weight`（change-balanced、§2.7）を渡す。
- **SHAP 対応**：両モデルとも TreeExplainer 対応（②の原因分析で流用）。

---

## 5. ドリフト検出（d×p 行列）

- 各セル `(d, p)` の値＝ **F1（＋適合率・再現率）**。
- **`d` を固定して位置 `p` を横断比較**し、F1 が落ちる位置を「変化区間」の候補として読む。
- 並べ替え検定（`PERMUTATION_N`, `SIGNIFICANCE`）で、位置依存が偶然でないかを検定（再学習なし、計算済み行列の並べ替えのみ）。
- 3 モデル・複数指標で多面的に確認し、ある指標だけで出た差は頑健な変化区間とみなさない。

## 6. 設定 `utils/constants.py`（後から変更可能な項目）

### 6.1 本設計で新規／変更する主要パラメータ
| 設定名 | 既定 | 意味・変更例 |
|---|---|---|
| `REVIEW_HORIZON_DAYS` | `7` | **Δ＝レビュー判定の期間（日）。1週間→1日 等に変更可** |
| `CHANGE_BALANCED_WEIGHT` | `True` | 学習の change 重み（`1/レコード数`）ON/OFF |
| `EVAL_CHANGE_BALANCED_WEIGHT` | `False` | 評価の change 重み ON/OFF（既定なし） |
| `N_TRAIN` | `500` | 学習 Change 数（固定） |
| `N_EVAL` | `"all"` | 評価 Change 数。`"all"`=全 Change、数値で固定数に切替 |
| `CLASSIFY_THRESHOLD` | `0.5` | 2値判定しきい値 |
| `ENABLED_METRICS` | `["precision","recall","f1"]` | 評価指標（後で `auc`/`mcc` 等を追加可） |
| `TRAIN_TAIL_MARGIN` | `True` | 学習ビン末尾 Δ の除外（リーク防止） |
| `EVAL_TAIL_MARGIN` | `False` | 評価の自主的末尾除外（絶対末尾は物理的に自動除外） |

### 6.2 旧実装から流用（引き続き設定可能）
| 設定名 | 既定 | 意味 |
|---|---|---|
| `MEASUREMENT_STEP_DAYS` | `1` | 計測点の刻み（日次） |
| `LOOKBACK_DAYS` | `365` | アクティブ判定の遡り |
| `BIN_COUNT` / `BINNING` | `6` / `"equal_time"` | ビン分割 |
| `BIN_DAY_ALIGNED` | `True` | ビン境界を 0 時に揃える（整数日幅）。Δ=計測刻み日なら学習末尾除外が厳密に 0 |
| `MIN_TRAIN` / `MIN_EVAL` | 既存値 | 供給不足セルの床 |
| `N_REPEATS` | `10` | セルごとの反復回数 |
| `REPEAT_AGG` | `"median"` | 反復方向の集約（中央値） |
| `RANDOM_SEED` | 既存値 | 反復のベース乱数（k 回目は seed+k） |
| `MODEL_NAME` | `["lightgbm","random_forest"]` | 使用モデル |
| `TARGET_PROJECTS` | nova＋versions | 対象プロジェクト・リリース |
| `PERMUTATION_N` / `SIGNIFICANCE` | 既存値 | ドリフト検定 |
| `PLOT_DPI` | 既存値 | 出力 |

> 旧 `T_AGG` は本設計では未使用（分類はプール集計のため）。

## 8. スコープ外・将来拡張

- **正例内の順位/回帰**：「Δ以内の早い/遅い」の順位は別の土俵。将来やる場合は、①Δ以内限定の順位相関 or NDCG（graded relevance）、②survival（Δで打ち切り）のいずれかで**別指標として**評価する（本書の2値評価とは分離）。
- **`decision_result`（merge/reject）**：別目的変数として後日。
- **②原因分析（SHAP 比較）**：本書のモデル・データ設計を流用し、新旧学習区間のモデルの SHAP を比較する。精度ゲート（両モデルが最低精度を満たすセルのみ解釈）を併用。
