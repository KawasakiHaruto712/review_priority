# lookback_window 設計書（事前分析窓長の調査：チューニング窓の長さはどれくらいが良いか）

## 0. 位置づけ・要旨
- 研究の流れ：**(1) チューニング窓の長さはどれくらいが良いか ← 本分析** → (2) 窓を固定して過去モデル等で変化が存在するか（`concept_drift_detection` の d×p 行列） → (3) 特徴量の違い（寄与分析） → (4) 近しい Change でチューニング（RQ2）。
- 本分析は「**評価日の直前でどれだけの期間（窓長）のデータでチューニングすると精度が良いか**」を、**日次でヘッドを貼り直して**測る。`concept_drift_detection`（距離 d ＝陳腐化）とは**測る対象が違い補完関係**（本分析は隙間≈0で「量」を測る）。
- **主目的は「適切なデータ量（窓長）の調査」**であり、変化は二の次。**主成果物は「窓長 × バージョンの要約表」**（§11.1）で、折れ線グラフは補助（§11.2）。
- **依存関係**：本分析は **`concept_drift_detection` に依存しない**（そのディレクトリが無くても動く）。共有部品（モデル・データ構築・特徴・label・Scaler・probe・embed）は**基点である `pretrained_encoders` から import**する。lookback_window **固有のコード**（窓スイープ・指標・保存・作図・実行）は**本ディレクトリで作成**する。
- 事前学習エンコーダ＋汎用ヘッドは `pretrained_encoders` が保存した**共有モデルを load**（本分析では学習しない）。凍結エンコーダの上で**線形ヘッドだけ日次で貼り直す**（linear probe は速いので日次で現実的）。
- 用語：レビュー対象の単位は **Change** で統一。

## 1. 目的変数
- `reviewed_within_delta`：計測点から **Δ 日以内**に人間レビューが付いたか(0/1)、bot 除外。**Δ = `REVIEW_HORIZON_DAYS` = 1 日**（正例の定義そのものを決める値）。
- label ロジックは `pretrained_encoders`（基点）から import。

## 4. 学習窓スイープ（本分析の主軸）
- 評価日 X について、**学習窓 = 評価日の直前 W 日 = [X − W, X − 1]**（**末尾は前日 X−1**。評価日自身は予測対象なので学習に入れない。特別なデータ除外はしない）。
- 窓長 **W ∈ {1, 3, 7, 14, 30, 60} 日**（絶対日数）。
- **窓が対象リリース開始／事前学習期間をまたぐのは許容**（評価日は常に窓より後なので目的変数リークは無い。エンコーダは凍結）。
  - 注意書き（考察用）：長窓（例 60 日）はサイクル序盤で**前サイクルの静かな期間**まで遡り、別レジームが混じって序盤だけ不自然に低く見えることがある。また**事前学習期間と重なり得る**（凍結表現上の線形 fit なのでリークではない）。バグではなく解釈上の注意。

## 6. 欠測ガード
- **probe 学習**：学習窓に **正例 ≥ 1 かつ 負例 ≥ 1**。
- **評価**：評価日に **正例 ≥ 1 かつ 負例 ≥ 1**。
- いずれか満たさない (評価日 × 窓長) は **欠測**（図では飛ばして次の点と結ぶ）。短窓ほど正例枯渇で欠測が増える。

## 7. 評価指標（全部出す → 描画は後から選ぶ）
出力する指標（(評価日 × 窓長 × seed) ごと）：
- **AUC**（主・**既定で先に描く**）。
- **precision / recall / F1**：しきい値 0.5 版 と **top-k 版**の両方。
  - top-k：その日の**全 Open Change をスコア降順**に並べ、上位 k 件を「見る範囲」とする。
    - `precision@k = 上位k件のうち実際にレビューされた件数 ÷ k`（見た範囲の的中率）。
    - `recall@k = 上位k件に入った正例 ÷ その日の全正例`（取りこぼさなかった割合）。
    - **k = 5, 10, 20, その日の正例数**。
- **MAP**（ランキングの平均適合率）。
- **正規化順位**（実際にレビューされた Change の順位を [0,1] に正規化して平均。上位ほど小）。
- **MRR**（レビューされた Change の順位の逆数の平均）。
- 汎用ヘッド版の各指標も同様に算出（基準線用）。
- 計算不能（欠測など）は **NaN**。
- 従来研究比較：van der Veen＝precision、Azeem＝AUC・top-k と対応づく。

## 8. 保存（2 段・後から自由に指標追加/描画選択できる形）
出力先：`data/analysis/preliminary_analysis/lookback_window/<project>/`
1. **生予測**（`predictions.csv.gz`）：**Change ごと** に `day, window, seed, change_id, y_true, score, is_missing, missing_reason`（汎用ヘッド分は `window="general"` 等で区別）。→ **モデルを回し直さずに新しい指標を後から計算**できる。
2. **集計指標テーブル**（`metrics.csv`, tidy）：`day, window, seed, metric, value`。描画はこれをフィルタするだけ。

## 9. 反復（seed）
- `pretrained_encoders` の保存 seed（既定 10 個）を使う。集約は中央値＋IQR。

## 10. 実行モードと描画指標の選択
`main.py` にモードを設ける（2 段保存があるので描画は再実行不要）：
- **`--mode run`（既定）**：encoder を load → 日次×窓長 probe → 生予測・指標を保存 →（続けて）作図。
- **`--mode plot`**：**保存済み `predictions.csv.gz` / `metrics.csv` から描画のみ**（モデルを回さない）。
- **`--mode recompute`**：生予測から**指標テーブルだけ作り直す**（新しい指標を足したいとき。モデル再実行なし）。
- **`--mode rank`**：保存済み `metrics.csv` から**順位集計表（1位/最下位カウント）**だけ出す（§11.3。モデル再実行なし）。

**対象プロジェクトの選択（全モード共通）**：
- **`--project <name>`**：対象プロジェクトを指定。**未指定なら `PROJECTS` の全プロジェクトを順に実行**（`all` も同義）。`PROJECTS`（§12）から**その project の cutoff・5版**を引く。関数（`run`/`recompute`/`draw`/`rank`）は **単一 project を引数でも受ける**（CLI だけでなくコードから直接呼べる）。
- `--mode run` で対象 project の事前学習エンコーダが不足していれば、`pretrained_encoders.build_and_save(project=...)` で**その project 用に自動作成**する（対象 project を正しく伝播）。

**描画指標の選択（run / plot 共通）**：
- **`--metric <name>`**：**指定した評価指標をそのままプロットする**（既定 `auc`。例 `--metric recall@10` なら recall@10 の折れ線を描く）。全指標は保存済みなので、指標を変えても**再実行不要で描き替えられる**。
- `--windows`：描く窓長を選択（既定は全部）。
- `--versions`：対象版を手動上書き（既定は `PROJECTS` の5版）。
- 汎用ヘッド（チューニングなし）の基準線は**デフォルトで重ねる**（`--no-general` で外す）。

## 11. 出力・図

### 11.1 要約表（主成果物）
- 本分析の主目的は「適切なデータ量（窓長）の調査」。まず **窓長 × バージョンの表**を出す（`metrics.csv` から生成・再実行不要）。
- **行＝窓長（2M / 1M / 2w / 1w / 3d / 1d）、列＝バージョン（26.0.0〜30.0.0）**。
- 各セル＝その (窓長 × バージョン) の**指標値 ± 標準偏差**（既定 AUC）。**セル内に小さく欠測データ量を併記**（例：`0.787 ± 0.147` の下に `欠測 0/180`。欠測量の文字サイズは現状維持）。
  - **値**＝日ごとに seed 中央値 → 評価日で平均。
  - **標準偏差**＝日ごとに seed 中央値 → **その日次系列の評価日方向の標準偏差**（ddof=1）。＝**期間内の AUC のブレ**（平均が良い窓が本当に安定して良いのかを見る）。値と同じ土台（日ごとに seed 中央値を取った系列）で算出。
- **右端に「Ave」列**＝**全リリースの全評価日をまとめた 平均 ± 標準偏差**（版を等重みにせず、**全評価日を等重み**で算出。日数が多い版ほど自然に効く）。＝どの窓長が平均的に良いか＝本分析の主結論。
  - **限界（typo3_cms）**：版の長さが 1〜13 か月でばらつくため、評価日 665 日のうち 14.0.0 が 406 日（約 6 割）を占め、
    Ave、したがって窓長の選択がほぼ 14.0.0 の成績で決まる（13.4.0 は 28 日で約 4%）。ほかの 5 件は 1 版の長さがそろっていて、各版の重みは約 2 割ずつ。
    **判定の決まり（① Ave → ② std）は変えず、限界として論文に書く**（2026-10-15 本人判断。版ごとの平均を等重みで平均する案は採らない）。
- **CSV（`summary_<metric>.csv`）**：各版の値の隣に std 列を置く（`window, 26.0.0, 26.0.0_std, …, 30.0.0, 30.0.0_std, Ave, Ave_std`）。欠測量は従来どおり別ファイル `summary_<metric>_missing.csv`。
- `--metric` で表の指標も切替（既定 auc）。

### 11.2 折れ線グラフ（補助・バージョンごと）
- バージョンごとに**ただの折れ線**：横軸＝日、縦軸＝指標（既定 AUC）。
- **p1〜p6 の破線・約1ヶ月ごとの集計テキストは入れない**（変化は二の次のため）。
- **窓長ごとに線**（色分け・**小さめマーカー**・欠測は飛ばして結ぶ）。**描く窓長は `PLOT_WINDOWS_DAYS`（constants）で選べる**（既定は全窓。例 1d/1w/2M なら `[1,7,60]`）。`--windows` で都度上書きも可。
- **凡例は残す**（**欠測日数を凡例に控えめ併記**：例 `1day (欠測 34/180)`）。
- **汎用ヘッド（チューニングなし）の基準線をデフォルトで重ねる**（`--no-general` で外せる）。

### 11.3 順位集計表（1位/最下位カウント。ブレの評価）
- **狙い**：要約表（§11.1）は「平均AUCでは1週間が良い」を示すが、**平均だけでは"ブレ"が見えない**。日次で各窓を順位づけ、**1位になった回数・最下位になった回数**を数えることで、**平均が良い窓が本当に安定して良いのか**を評価する。
  - 例：短窓 1d は**日次AUCの分散が大きく、1位も多いが最下位はもっと多い**（＝まぐれ勝ちのノイズ）。1位だけでなく**最下位も併記**すると、この「ノイズか本物か」が一目で分かる。
  - **ビン集約はしない**（日次のまま）。集約は距離×時期行列の分析（`concept_drift_detection`）側に閉じ込め、窓長の調査は日次で評価する。
- **集計方法**：
  - `(版, 日, 窓)` で **seed 中央値**をとった AUC を作る（要約表 §11.1 と同じまとめ方。2026-10-05 に seed 平均から変更。要約表は当初から中央値で、順位の集計だけが平均になっていた）。
  - **全窓（1d〜2M の 6 窓）が揃う日**だけを対象（公平な順位づけのため）。**汎用ヘッド `general` は順位から除外**。
  - 各対象日について、**最高 AUC の窓に「1位 +1」、最低 AUC の窓に「最下位 +1」**。
  - **同着は両方加算**（AUC の厳密一致で判定。float なので稀）。この結果、**各窓の 1位率の合計は 100% を超えることがある**（同着ぶん）。
  - 率＝**回数 ÷ 対象日数**。
  - （2026-10-21 追加）「小さいほど良い」指標（`LOWER_IS_BETTER`。今は `norm_rank`）では、最低の窓に「1位」、最高の窓に「最下位」（§16）。
- **表（CSV 1 枚。図は出さない）**：
  - **行＝窓長（2M → 1d の降順、§11.1 と同じ並び）**。
  - **列＝版（26.0.0〜30.0.0）ごと＋「全体」（全版プール）**で、各グループに `_1位 / _最下位 / _1位率 / _最下位率` の 4 列。
  - **冒頭に対象日数のコメント行**（例：`# 対象日数: 26.0.0=148, 27.0.0=125, ..., 全体=639`）。1 ファイルで完結。
  - 指標は既定 **AUC**（`--metric` で切替可、ファイル名は `rank_<metric>.csv`）。
- **保存先**：`data/analysis/preliminary_analysis/lookback_window/<project>/summary/rank_<metric>.csv`（§11.1 の `summary_<metric>.csv` と並ぶ）。

## 16. 今回の論文の 6 件の結果と窓長の決定（2026-10-21 追加）
- 実行：研究室のサーバ（CUDA）で 6 件を 1 つのプロセスで順に、約 6 時間 10 分（CPU 1 コア・GPU 使用率 4%。probe を 1 本ずつ学習するので GPU の速さが効かない。
  以後の分析はリポジトリごとに並べて回す。`pretrained_encoders/design.md` §14.7）。
- AUC・recall@10・recall@pos の 3 つで要約表・順位の集計・6 件の報告用の表を出した（`--metric`。`report/rank_<metric>_all.*`・`best_<metric>_all.*`）。
  - 3 つとも「**1 日は悪い・3 日はやや悪い・1 週〜2 か月はほぼ同じ**」。1 日の最下位率は 40〜67%。AUC は 0.90〜0.94（OpenStack は 0.78〜0.89）。
  - **汎用ヘッドとの差**：AUC では +0.001〜0.004 と小さいが、recall@pos では 4 件で +0.012〜0.019（直前の窓での学び直しは上位の並びに効く）。qtbase・qtcreator はほぼ 0。
  - recall@10 は上限 10 ÷ 正例の数（qtbase は 1 日の正例が中央値 42 件で上限 0.24）のため、リポジトリの間の比較には向かない。recall@pos は上限が 1 で比べられる。
  - recall@10・recall@pos は値が飛び飛びのため同着が多い（6 つの窓長がすべて同じ値の日が 9〜20%）。1 位率の差は読みにくい。
  - go・qtbase は後の版ほど recall@pos が下がる（go 0.430 → 0.374、qtbase 0.371 → 0.340。2w）。事前学習の締め切りから離れるほど表現が古くなる可能性（RQ1 で確かめる）。
- **窓長は recall@pos の最良**に決めた（本人判断。`concept_drift_detection/design.md` §4.2）：qtbase 2M・qtcreator 1M・mediawiki 2w・qtdeclarative 2w・go 1w・typo3_cms 1w。
- 指標の注意：順位の集計（§11.3）と報告用の表（§11.4）は「大きいほど良い」前提。`norm_rank`（小さいほど良い）では 1 位と最下位・最良が逆になる（使うなら直す）。
  → **2026-10-21 直す（本人判断。窓長の設定の書き入れと一緒に）**：
  - 「小さいほど良い」指標の一覧を定数 `LOWER_IS_BETTER = {"norm_rank"}` として 1 か所に置く（今後同じ向きの指標が増えたらここに足す）。
  - 順位の集計（§11.3）：その指標のときは、その日に**最も小さい**窓長を 1 位、**最も大きい**窓長を最下位にする（同着の扱いは同じ）。
  - 報告用の表（§11.4）の「最良」：その指標のときは、平均が**最も小さい**窓長を最良にする。1 位率・最下位率の表の太字（1 位率の最大・最下位率の最小）は、
    順位が正しくなればそのままでよい。要約表（§11.1）と図は向きを使わないので変えない。
  - `norm_rank` 以外の指標の結果は変わらない（テストで確かめる：AUC の結果が今と同じこと、`norm_rank` で向きが逆になること）。
  - `feature_space_window` の順位の集計・報告用の表（複製）も同じに直す（`feature_space_window/design.md` §5.1・§5.2）。
